# Waypoint

Waypoint is a collaborative project management app for organizing work across teams and workspaces. It includes project tracking, assigned tasks, task discussions, and workspace-based access.

## Features

- Sign in with Clerk and create or join workspaces.
- Manage projects, team members, project status, priority, and progress.
- Create tasks with assignees, due dates, types, priorities, and status.
- Discuss tasks with comments.
- View dashboard counts, project analytics, and project calendars.
- Receive email notifications when added to a project or assigned a task.
- Delete a workspace as its creator, including its projects and related work.

## Tech stack

- **Client:** React, Vite, Redux Toolkit, Tailwind CSS, React Router
- **Server:** Node.js, Express
- **Authentication and organizations:** Clerk
- **Database:** PostgreSQL, with Prisma and the Neon serverless adapter
- **Email and scheduled events:** Nodemailer and Inngest

## Repository layout

```text
client/   React/Vite application

```

## Run locally

You’ll need Node.js, npm, a Clerk application with Organizations enabled, and a PostgreSQL database. Email and Inngest configuration is needed for the related notification and reminder workflows.

### 1. Install dependencies

In separate terminals, install the client and server packages:

```bash
cd client
npm install
```

```bash
cd server
npm install
```

### 2. Configure the client

Create `client/.env`:

```env
VITE_BASEURL=http://localhost:5000/api
VITE_CLERK_PUBLISHABLE_KEY=pk_test_replace_me
```

### 3. Configure the server

Create `server/.env`:

```env
PORT=5000
NODE_ENV=development
FRONTEND_URL=http://localhost:5173

DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
DIRECT_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require

CLERK_SECRET_KEY=sk_test_replace_me

SMTP_USER=
SMTP_PASS=
SENDER_EMAIL=

INNGEST_EVENT_KEY=
INNGEST_SIGNING_KEY=
```

Use the database URLs, Clerk keys, and mail credentials from your own services. Keep both `.env` files private; do not commit secret keys or database credentials.

### 4. Set up the database

From `server/`, apply the Prisma schema to a new or prepared database:

```bash
npx prisma db push
```

Review any Prisma warnings before applying schema changes to a database that already contains data.

### 5. Start the app

Run the API in one terminal:

```bash
cd server
npm run server
```

Run the client in another terminal:

```bash
cd client
npm run dev
```

Open [http://localhost:5173](http://localhost:5173). The API listens at [http://localhost:5000](http://localhost:5000), with application endpoints under `/api`.

## Email and scheduled events

Task assignment and project membership notifications use the server’s SMTP configuration (`SMTP_USER`, `SMTP_PASS`, and `SENDER_EMAIL`). Workspace invitation emails and due-date reminders use Inngest. The Express app serves the Inngest endpoint at `/api/inngest`; configure that endpoint and the Inngest keys for the environment where those workflows should run.

## Deploy on Vercel

The repository has separate client and server Vercel configurations. A typical setup uses two Vercel projects:

- **Frontend:** set the project root to `client`. Vercel builds the Vite app with `npm run build` and publishes `dist`. Set `VITE_BASEURL` to the backend URL ending in `/api`, and set `VITE_CLERK_PUBLISHABLE_KEY`.
- **Backend:** set the project root to `server`. The included `server/vercel.json` routes requests to the Express app. Configure the server environment variables in Vercel, including database URLs, Clerk’s secret key, `FRONTEND_URL`, SMTP, and Inngest settings.

The client’s `dist/` folder is generated by the build. Vercel can build it from the tracked source; it does not need to be committed when the frontend project uses the `client` root and runs the Vite build.
